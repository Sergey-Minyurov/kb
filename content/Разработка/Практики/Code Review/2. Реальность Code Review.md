[[1. Основы Code Review]]

При лобовом применении проверки кода (карго-культ, без методологии и адаптивного процесса на основе обратных связей) возникают следующие проблемы:
- Информационная перегрузка проверяющего, необходимость отвлекаться от собственных задач и значительные временные затраты.
	- Снижается производительность самого проверяющего.
	- Задержка внедрения нового кода.
	- Блокировка зависимых задач других разработчиков. 
- Неоднозначность понимания задач и технических решений в силу разного опыта.
	- Значительные затраты на дискуссии и переделки, навязывание односторонних решений. 
	- Не всегда адекватные совместные решения из-за недостаточного погружения в контекст в силу дефицита времени и внимания.

При осознании этих проблем можно попытаться упорядочить (бюрократизировать) процесс, разработать регламенты и метрики для его контроля. Но при поверхностном и формальном подходе это только усугубит проблемы.

В результате может быть снижение производительности всей команды и её демотивация.
